Honest Assessment

What this architecture cannot do

This is a batch analytics agent. It queries pre-computed, historical snapshots. It is categorically different from an agent with live API access to transactional backends.

Data is always stale

Gold tables reflect the last pipeline run — not what happened 5 minutes ago. A supplier could have submitted an invoice 10 minutes ago and this agent has no knowledge of it. For procurement operations requiring real-time visibility, this architecture fails entirely.

Cannot take action

This agent reads only. It cannot approve a PO, reject an invoice, send a supplier notification, update a risk rating, or trigger any workflow in SAP, Coupa, Ariba, or any ERP. It is a read-only analytics window, not an operational agent.

Answers limited to Gold schema

If a question requires data that was not aggregated into a Gold fact table, the agent cannot answer it. "Show me the line items on PO 00001234" requires Silver data. "What is the current open PO count right now" requires a live ERP call. The Gold layer trades completeness for speed.

LLM-generated SQL can be wrong

Claude generates SQL based on schema descriptions in the system prompt. It can hallucinate column names, produce logically incorrect joins, or misinterpret ambiguous questions. Every result should be treated as indicative, not authoritative, without human validation.

The right architecture for your organization is almost always both. A batch analytics agent (this POC) handles strategic KPI reporting, trend analysis, and executive dashboards. A live API agent handles operational workflows — approvals, alerts, and real-time lookups. They are complementary, not competing. The data warehouse feeds the analytics agent. The transactional system feeds the operational agent.
